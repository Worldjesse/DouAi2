# 0.1.71：评论回复并入自动回复

本地构建版本 `0.1.71 / 72`。评论回复作为「自动回复」的接收子项，沿用原有列表和配置；不再提供独立的评论回复提示词、模式、额度或历史设置页。

## 使用

1. 打开「自动回复」，配置回复模式、回复内容和发送设置。
2. 打开「开启自动回复」，按需选择「接收私聊」「接收群聊」「接收评论回复」。只接收评论回复时，可以关闭私聊和群聊接收。
3. AI 模式使用父级「回复内容」里的模型与二级提示词；固定内容、关键词规则和随机内容也按父级配置处理评论回复。
4. 从「发送与记录 → 回复历史记录」查看各类自动回复，评论回复记录会标明来源。

「接收评论回复」不会替用户打开父开关。子项已选中而父开关关闭时显示暂停；互动自动化总开关不替代自动回复父开关。使用“立即停止”仍会关闭全部自动功能。

## 共用设置

| 父自动回复设置 | 评论回复行为 |
| --- | --- |
| 回复模式与内容 | 复用固定正文、AI、关键词或随机规则；关键词只匹配对方来评，无匹配不发送 |
| 模型与提示词 | 使用同一模型配置、一级及回复二级提示词；原生确认成功后才记入当前评论线程的模型上下文 |
| 语音回复 | 使用同一 TTS 来源和参数，走原生评论语音上传；不同时再发文本，准备失败不静默改文本 |
| 发送延迟 | 使用父级延迟，至少两秒，延迟期间可因关闭功能、离开前台或切号取消 |
| 每日额度与用户间隔 | 评论回复和私信/群聊共用额度账本；同一 UID 共用间隔，不再读取旧的独立额度 |
| 悬浮提示 | 使用父级开关和时长，可取消尚未提交的回复 |
| 保存历史 | 使用父级开关并合并到回复历史；清空父回复历史同时清理评论回复展示记录 |

旧 `comment_reply_*` 配置值保留用于旧备份兼容，但不再用于运行决策。独立去重账本继续按账号和收到的评论 ID 工作；清空展示历史不会让已提交或未知结果再次发送。

## 保留的评论入口行为

使用抖音时监听互动并增量扫描，冷启动及返回前台时补扫；首次开启建立基线，不追发已有旧评论。只处理能够核实为对本人评论的回复，不把无关评论或提及当成目标。私聊与群聊各自的接收范围仍分别配置。

评论目标使用捕获的作品和被回复模型，不随当前视频变化。楼中楼回包必须匹配作品、根评论与目标评论才确认成功；已提交但超时或未知的结果不自动重发。评论线程保留内部三次防循环保护；该保护不是单独可调的回复设置。评论语音当前保留模块 30 秒保护，私信/群聊语音仍为 120 秒。

外层列表共 12 项，重复的独立设置页和灰色说明已移除。实现基础与宿主接口证据见 [0.1.70](release-0.1.70.md) 和 [接口分析](2026-10-17_reverse-douyin-comment-reply-report.md)。
