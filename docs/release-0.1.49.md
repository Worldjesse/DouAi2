# DouAi 0.1.49

版本 `0.1.49` / versionCode `50`，沿用正式包名、发布签名和 R8 配置，资源裁剪关闭。宿主适配为抖音 40.6.0 / 400601。

本版为本地修复记录，改动已并入 [0.1.50 正式版](release-0.1.50.md)。

## 反馈与修正

用户反馈 0.1.48 仍有视频不显示进度条，补充确认暂停后临时显示组件能恢复；实际进度条设置为 `124`。底部导航改回 255 是否能恢复，用户随后明确表示不确定，不作为确定根因。

`255` 会跳过模块透明度处理，`124` 会进入处理。原先正数模式固定首次 Alpha，若宿主加载进度条时 Alpha 为 0，随后设置为 1，模块仍会反复施加 0。新增回归 `progressAt124FollowsHostFadeInAndRestoresTheLatestHostAlpha` 在修复前失败，预期 `0.4862745`、实际 `0.0`。

修正为仅对进度条目标在正数模式下跟踪宿主后续 Alpha，仍以宿主基准 Alpha 乘以配置值 / 255；每次记录模块实际施加值，稳定重绘不重复相乘。暂停显示、关闭隐藏或改为 255 恢复宿主最新状态；宿主自己隐藏的进度条不强制显示。目标拆分保留进度条归属，挂载容器也使用相同策略。

数值语义保持：`-1` 使用 INVISIBLE，完全不可见但保留布局位置；`-2` 使用 GONE，移出布局计算；`0..255` 为透明度，`124` 在宿主 Alpha 为 1 时对应约 48.6%。没有把 -2 替换成 INVISIBLE 或透明度 0。共享容器内其他组件仍按各自值处理。

另补精确 `com.ss.android.ugc.aweme.feed.widget.ChapterOuterSeekBar` 类型及经宿主资源表确认的 `2131369826 / d5s`。它在宿主中继承 FrameLayout，不属于既有三个进度类型。没有把包含其他占位视图的 `x6x` 整块当成进度条。此静态遗漏并不能证明截图中的视频使用章节进度。

## 有限诊断

对于保留的进度条（配置大于 0），选中视频、切换配置或临时显示时，在当下、750ms、3000ms 采样。每进程选中视频与设置变化分别限制为 18 次采样，不在每帧写日志；关闭或暂停当前卡片时取消待执行任务。

日志前缀为 `Feed progress snapshot=`，记录实际进度值、底部工具/导航配置、真实控件及祖先的 class/宿主资源名、visibility、Alpha、测量/布局尺寸、位置/位移、可见矩形、裁剪和模块施加值。扫描整个当前窗口，以覆盖卡片外的页面进度；当前卡片和页面 CustomizedUISeekBar 优先于预加载卡片。单次最多 4096 节点、64 层、6 候选、每候选 12 祖先、18000 字符。

不读取或输出视频文案、账号、视频 ID、contentDescription、tag；只记录经过宿主包名检查的资源名。诊断只读，不更改视图。外部控制器施加的隐藏不一定有模块目标标签，应结合祖先状态判断。

## 设备复验

覆盖安装后完全退出并重新打开抖音。保留进度条原设置 `124`，其余设置继续使用原值，在此前问题视频上检查正常播放、暂停显示、继续播放及切换视频。

若仍出现，停留在该视频，暂停让组件显示，再继续播放并导出 LSPosed 日志；这会提供同视频隐藏/显示的诊断对比。没有真机连接，代理未在用户手机上复现具体视频，不能把本地回归通过等同于设备验收。未安装、提交或发布。
