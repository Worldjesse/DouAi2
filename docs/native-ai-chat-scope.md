# 原生 AI 聊天界面适配范围

## 授权与目标

- `auth`：用户要求将消息内的 AI 聊天界面采用抖音官方页面，并明确要求实现；本次静态分析服务于该本地模块功能。
- `in_scope`：工作区内的抖音 40.6.0 APK、已有 jadx/smali/资源解包结果，以及 DouAi 消息联系人入口和本地 AI 会话界面；用户提供当前/官方截图后继续修正视觉差异，并按后续要求调整模型配置页头像入口和联系人开关位置。
- `network_profile`：静态分析与布局核对均为离线；不连接设备，不请求抖音接口，不建立或发送官方 IM 消息。
- `flavor`：`null`，普通 APK 界面合同分析。

## 实施边界

采用官方根布局、`ChatTitleUI` 标题文字、`TextOnlyCellUI` / `IMMsgTextView` 文字气泡、`AvatarCellUI` 圆头像、官方消息行壳、资料卡及快捷卡片工厂，以及 `InputDrawerUI2` 输入栏和其原有发送控件；图标与背景从宿主资源及主题方法读取。点击动作、资料/卡片内容、消息数据、发送/附件监听器由模块绑定。DouAi 的模型配置、历史记录和 API 客户端驱动会话。官方界面资源的复用不表示消息进入抖音官方会话，不创建虚构 UID，也不接入官方 AI 服务。

自己的头像读取当前账号本地模型中的头像字段，并交给宿主正常头像加载器；模型头像使用已保存配置。语音按钮由用户点击后调用设备的系统语音识别 Activity，仅将文字填入草稿，不调用官方录音上传/IM 发送。模型配置中的头像操作集中在头像点击菜单，联系人开关位于表单底部。

三个官方根布局分支的顶部、消息和输入槽位重新挂到同一原生主纵向区域，消息区按剩余高度伸展，输入区按内容包裹；移除需要官方 IM 逻辑驱动的覆盖层和原始 275 dp 面板占位。根视图使用宿主原生主题取色并检查为不透明，不让全屏对话露出底下的消息页。

原生 `RipsChatRoomFragment` 的参数入口和依赖仅作方案评估。完整官方 Fragment 会启动 Rips、会话模型和业务组件，本轮选择独立使用其布局及控件，避免将模块 AI 会话绑定到官方 IM 数据层。

## 证据与验收边界

静态证据详见 [原生聊天页面适配记录](2026-10-18_reverse-native-ai-chat-report.md)。桥接仅接受源 APK `40.6.0 (400601)`；资源 ID 和混淆方法需要随宿主版本复核。无法初始化官方控件时明确提示本次适配失败，不静默切换为旧对话样式。

本地构建、单元测试或资源合同检查只能验证对应层面的行为。真机上的官方资源加载、键盘、系统主题、布局分支、附件返回及消息页切换尚需单独验收，不能由静态阅读代替。
