## 短视频进度

用户选择短视频播放时常显，并继续使用 124 等数值控制透明度。

- 旧实现：宿主 `X.1QBp.LIZ(Aweme, Integer)` 将部分不超过 30000ms 的视频判为默认隐藏，CustomizedUISeekBar 据此选取 Alpha 0 状态；暂停进入另一状态。
- 新实现：`FeedBizSeekBarComponent.LJJJJJL` 调用 `X.1PIm.LIZ(Aweme)` 判断短时长隐藏并选择 ProSeekBar 的默认状态。
- 新增两条经完整 DEX 唯一性验证的扫描规则，在组件隐藏已配置、开启且进度值大于 0 时，让普通短视频使用原生可见默认。原生进度更新、状态转换及拖动继续由宿主负责，没有强制显示缓冲动画条或单独绘制假进度。
- 限定普通非广告视频（Aweme type 0、视频对象存在、时长 1..30000ms）。广告、图集、未知时长及其他类型保留宿主原始判断。0、-1、-2 和总开关关闭时，不覆盖短时长隐藏判断。
- 补 `com.ss.android.ugc.aweme.o.seekbar.views.seekbar.ProSeekBarView` 精确类型；页面级的 ProSeekBar/CustomizedUISeekBar 也应用进度设置，搜索排除卡片根以避免影响预加载卡片和重复施加透明度。
- `124` 在宿主基准 Alpha 为 1 时对应 124/255；-1 为 INVISIBLE，-2 为 GONE。暂停临时显示、关闭配置或改为 255 时释放模块施加值。原生默认状态在绑定作品时生成，改变常显启用条件后切换视频可重建当前作品的默认状态。

规则指纹更新为 `12039abcf939f2afe473416551cf75076ed18d978cb0bbcf3418908c121f48b9`，启动缓存会因规则变化失效重建。诊断新增旧、新短进度策略安装状态，并能记录 ProSeekBar 及页面进度的实际施加值。

## 自动评论与回复

自动评论仅由 `native_auto_comment` 控制；自动回复仅由 `native_auto_reply` 控制。移除入口、队列、生成结果预览、调度倒计时及回复发送前的互动总开关依赖。仅切换互动总开关不会取消已准备的评论或延迟回复。诊断中的启用状态同步采用新语义。

各自开关关闭、目标/账号变化、范围过滤、历史消息排除、去重、取消预览和发送前复核继续有效。“立即停止”仍显式关闭两项功能。续火花继续按其原有开关与互动总开关校验，并在原生调用前再次检查。

另修复默认私聊范围的变更检测：配置未保存该键时默认允许私聊，后来明确关闭时也会使待发回复失效。回归在修复前错误记录为 sent，修复后取消且不调用模拟原生发送器。

## 设备复验

覆盖安装并完全重启抖音，等待适配扫描完成后切换一条视频，让原生默认状态重新生成。开启组件隐藏，进度条先保持 124，其他值保持原设置；对普通短视频检查播放、暂停、继续播放及切换。再检查 255、-1、-2。

保持互动自动化关闭，仅开启自动评论或自动回复各自开关；按既有目标范围与预览确认设置复验。关闭各自开关或点击立即停止后，应不再产生新任务。改变短视频常显条件后切换视频，以重建原生默认状态。

代理未连接真机或使用用户账号发送。原生 SDK 流程、取消和回调由本地替身验证；测试通过不等同于截图中视频或真实账号发送已完成设备验收。
