# 0.1.85：本地分析 Responses 流式接收与摘要预算

版本 `0.1.85 / versionCode 86`，本轮本地交付。

## 已确认的故障与边界

使用者确认模型为第三方中转的 `deepseek-v4.1-flash`，模块接口协议为 OpenAI Responses，中转支持流式。普通文字、文件、视频和图片请求可用；将模型超时从 30 秒改为 120 秒并保存后，本地分析仍失败。

`LSPosed_20261018_204801.zip` 中两次分析从发出到 HTTP 504 分别为 60.640 秒和 60.344 秒，均未进入本地结果解析。使用者提供的后台记录显示同步请求和 1 分 22 秒的总耗时，支持请求到达上游后，返回链路先达到等待期限这一解释；尚不能从这些证据确定具体哪一级网关或其计时策略。[504 的标准语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.6.5)是网关未及时收到完成请求所需的上游响应。

摘要字符数并未被证明是本次 504 的原因。16000 字符是模块文本附件的独立兼容约束；直接输入的文本消息另有 4000 字符限制。此前为边界实验生成的长文件在 JSON 开头放入空白，复制时会被输入过滤截在空白区，不适合作为粘贴成功与否的证据；已提供修正示例。

## 本轮调整

仅本地分析的 Responses 请求启用 `stream=true`。保持当前模型、鉴权、全局提示词与不保存对话的设置，仍为一次 POST，不自动重试或重新发送。普通聊天及其他协议保持原路径。若中转在同一个连接返回 JSON，保留兼容处理；显式 `incomplete / failed` 或错误状态不能被当作成功。

按 [Responses 流式事件文档](https://developers.openai.com/api/reference/resources/responses/streaming-events)接收正文增量与完成事件，完成快照不与已收增量重复拼接。推理、工具和未知事件不作为分析正文，不记录其内容。只有完整结束并满足 11 字段、单项及总长度校验后才展示与记录分析成功；断流、错误和未完成状态明确失败。

总等待预算由所选模型的超时配置决定。仅 Responses 分析通过有界后台 IO 任务执行，等待方超时或取消后不再发布结果，旧请求不能清理或取消下一请求。平台仍阻塞的 socket 读取或关闭可能在有界后台等待其自身超时，不承诺物理连接在预算边界瞬时释放。流式接收保留字节、帧、单行、单事件和最终正文上限，推理帧仅消耗有界传输预算，不进入最终解读。

流式用于改善等待整包生成期间连接没有内容返回的情况，不能保证绕过中转的固定总时限、首包延迟或上游故障。其原理见[官方流式指南](https://developers.openai.com/api/docs/guides/streaming-responses)。

统计摘要附件同时控制为最多 16000 字符、32768 UTF-8 字节。先省略重复的 7/30 天比较，再省略重复矩阵和本地叙述；必要时省略已在顶层保留的本期重复排行。保留原始关键计数、排行、所选范围对比的日期/计数/前期排行/完整性、真实关联和采集边界，注明省略范围。极端情况下仍超过预算时，发送前拒绝，并明确提示缩小范围，不截断 JSON。
