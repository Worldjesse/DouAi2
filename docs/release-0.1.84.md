# 0.1.84：本地 AI 分析失败诊断与格式边界

版本 `0.1.84 / versionCode 85`，本轮本地交付。

使用者反馈本地分析等待一段时间后失败，而模型设置中的测试请求正常。原提示将请求和返回校验问题合并为“分析失败或模型未返回完整图表解读，请检查网络及模型配置后重试”，不能据此判断 AI 服务不可用。

## 日志证据与范围

检查 `LSPosed_20261018_201149.zip` 的当前和历史模块日志，未发现本地分析请求阶段或解析结果的诊断。当前日志中的自动评论 AI 请求有 HTTP 200；HTTP 402 来自自动评论的合成阶段，属于其他调用链，不能作为本次人物分析失败的原因。

原分析流程丢弃了底层异常类型，故这份日志不足以确认设备上究竟发生了格式拒绝、超时或其他请求错误。新版本提供受限诊断；没有在使用者设备上重放请求，也没有调用真实模型。

随后使用者安装本诊断版，并提供 `LSPosed_20261018_204801.zip`。新日志确认两次 Responses 分析：20:34:23.573 发出、20:35:24.213 收到 HTTP 504，耗时 60.640 秒；20:38:07.968 发出、20:39:08.312 收到 HTTP 504，耗时 60.344 秒。均没有进入 `received / validate / complete`，所以这一轮失败发生在请求链路，而非本地 JSON 校验。504 表示网关未及时收到所需的上游响应，见 [RFC 9110 第 15.6.5 节](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.6.5)。重复时长支持网关等待限制这一推测，具体哪一层及触发因素仍不能仅凭日志确定。

## 可复现问题与修正

通过本机 MockWebServer，使用真实 `AnalyticsAiAnalysis.prepare(...).run()` 调用链，在修改生产代码前执行了两个失败用例：

- HTTP 200 已返回文本，但文本不符合分析 JSON 结构，原代码仍将错误统一提示为检查模型配置。
- 11 个字段完整且各段合规、标准化 JSON 为 3995 字符时，外层代码围栏和空白使传输文本略超过 4000 字符。`parseResult` 原本接受该形式，但共享文本客户端在解析之前将其拒绝。

第二项是已确认的兼容性边界，并未证明使用者这次恰好遇到了该边界。

分析继续要求完整分图解读和综合侧写，不增加自动重试或额外请求，不改变普通对话输出上限，也不修改现有全局提示词。页面显示受限的错误分类，诊断连接到宿主的 LSPosed 日志；只保留阶段、枚举、状态码、长度与结构计数，不记录接口、凭据、请求/回复正文、作者、话题或个人自述。

本地分析使用已保存并选中的模型配置；测试对话可以使用未保存的编辑草稿。分析不读取测试对话上下文。使用者截图中超时为 30 秒，随后反馈改为 120 秒并保存启用后仍失败，因此单纯延长超时未解决本次故障，不能将其认定为超时原因。温度、Top P 和 Token 开关关闭时不发送相应可选参数；Claude 分支无显式 Token 设置时仍保留既有 1024 默认值。
