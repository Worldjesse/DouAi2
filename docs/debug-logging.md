日志现在使用统一结构化事件。全功能台账、字段与结果语义见 [日志规范](logging-events.md)、[覆盖矩阵](logging-coverage.md)，本次验证见 [测试结果](logging-validation.md)。

本说明随 **0.2.16 / 117** 发布，覆盖矩阵登记 **58 项业务能力、28 个配置消费者族**。日志源码修复阶段的历史测试保留原结果；0.2.16 已构建原签名正式包，按此前要求跳过本轮本地测试和 Lint，构建与验证边界见 [0.2.16 发布记录](release-0.2.16.md)。尚未完成本版真机验收，旧安装包和旧设备日志不能证明当前源码已经在手机生效。

## 选择简单或详细日志

“关于 → 调试与日志 → 全局调试日志”使用同一个开关，同时控制模块日志文件与 LSPosed 输出的明细等级，保存后立即生效。

| 开关 | 两处输出 | 排查范围 |
| --- | --- | --- |
| 关闭，`log_mode=simple` | 功能状态、根操作开始与终态、必要决策、简要异常、完整性与丢失说明 | 判断为何执行或跳过、最后结果及简要依据；常规阶段、逐键配置、Hook 明细与异常栈省略 |
| 开启，`log_mode=detail` | 简单模式内容，加详细阶段与子操作、配置快照及选择、Hook 类型与耗时、异常栈 | 按 `trace_id` 复核执行过程、异步关联、配置依据与故障位置；高频重复记录仍会汇总 |

关闭开关只影响之后生成或投递的记录，已经落盘的明细仍可查看、复制和导出。若要只看切换后的新记录，先清空日志，再触发功能；清空不会取消业务，也不会创建新的 `session_id`，新进程会话需要重新启动宿主。两种模式都遵守同一脱敏规则，开启明细也不采集评论、私信、AI正文或凭据。

## 排查一个功能

1. 在“关于 → 调试与日志”选择明细等级。若需要复核完整执行过程，先开启调试日志、清空历史记录，再复现并导出宿主日志；可同时提供同次复现的 LSPosed 日志。
2. 查功能的 `feature_state`：配置启用、依赖可用、Hook安装、实际观察与最近结果分别说明。安装成功不等于功能效果已经验证。
3. 按 `trace_id` 查看触发与根 `operation_finished`；详细模式另有资格判断过程、阶段、尝试和子span。请求接受、方法调用返回、HTTP 200与实际业务成功严格区分。
4. 判断结果时同时看 `reason_code` 和 `evidence`。成功可能只证明当前View属性、本地产物或明确业务回执；无法观察最终效果时是 `unconfirmed`。
5. 检查导出的完整性清单：队列丢弃、抑制、轮转、清空、存储错误、开放操作及上个会话未闭合span。未观察到的框架裁剪标为unknown，不报零。

日志页面可搜索trace/feature/reason，结果分类只把根操作终态计入结果，子阶段不增加成功次数。复制保留当前筛选，完整导出不受筛选影响。

## 隐私与容量

默认日志只保留必要事实、数量、长度和会话内引用；评论、私信、AI输入输出、凭据与原始异常正文不写出。打开明细也不会恢复旧版自动正文JSON采集。主动“查看评论数据”仍是用户操作的原有功能，与后台日志不同。

业务队列256条、活动span256个、文件两份各1MiB、内存尾部128KiB，均有上限。重复Hook、播放、布局按状态变化/窗口/计数汇总。诊断失败不改变业务返回或重试策略。强杀、OOM、存储失败及外部框架裁剪无法保证零丢失；导出必须结合完整性说明使用。

宿主私有文件经原有指定包名和签名权限通道导出，独立模块应用不直接读宿主私有目录。宿主未运行或通道不可用会明确显示不可用。

清空会隔离尚未落地的旧队列；它不会取消业务操作，后续业务结果仍会生成新日志。运行中的任务在导出中显示未闭合；下次启动可从已成功落地的journal链接旧session与trace，无法推测具体终止原因。

## LSPosed记录

正文自带level/feature/event/session及`log_mode`。LSPosed 与模块日志使用相同的简单/详细模式投影；关闭开关后 LSPosed 同样省略常规阶段和明细。框架外层日志级别不代替内部严重度。较大事件按相同event_id、trace_id与校验值分片，须完整重组后分析；本地文件保持单条结构化事件。仅提供片段或被裁剪日志时，结果完整性保持未知。

独立模块应用在启动时初始化自己的私有日志。“导出”仍读取原宿主通道；“导出模块进程日志”只导出当前模块包的日志，宿主不在线时也可使用。两份日志保留不同session与进程标识，不假装跨包直接读取，也不把本地可用冒充宿主连接成功。
