## 阈值假说的边界

- **原始 30 秒必拒不成立。** 30,600 ms 的自动评论已成功并有音频元数据；这不证明服务端没有取整、转码或其它处理，也不代表任意更长音频都会成功。
- **空 `wave` 必拒不成立。** 所检模块路径对这些 owned 音频使用同样的空波形，但已有成功。波形是否在特定条件下影响结果仍未知，不能扩大为“任何空波形均无影响”。
- code 5 发布失败的最小样本为 **31,716 ms / 509,172 字节**，已经低于 512,000 字节及 512 KiB，不能把上传分片 512 KiB 当成充分成功条件。
- 约 500,000 字节或约 31 秒附近仍可能存在某种约束，但没有证明。全部 25 组满足 `bytes = 16 × audioMillis + 1716`，时长与字节量完全共线，无法仅靠这些样本区分两者。
- 30,996 ms / 497,652 字节的三次失败属于检查直接拒绝，不能当作“低于 500,000 字节仍发生 code 5 发布失败”的反例。≤30 秒仅有 2 条成功，其中 1 条为评论回复；≤5 秒没有样本。

本批 22 个语音失败后的任务在第三次失败至决定文本回退之间为 0.027–0.247 秒，中位 0.047 秒，未重现旧样本约 21 分钟空窗；这不解释旧空窗的成因，也不是性能基准。
