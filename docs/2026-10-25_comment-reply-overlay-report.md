## 修正路径

原路径：持久化 claim → 本地等待 → 素材 → 模型 → 语音 → Dispatcher ready/预览 → 原生发送。前四个准备阶段尚未进入展示状态表，慢生成时就没有进度浮窗。

新路径在 claim 成功后即登记等待态，素材、模型和语音阶段更新同一条 `comment_reply` 展示记录；ready 后复用同一 Pending 和浮窗，进入原来的发送预览及原生提交路径。未更改发送提示开关、预览时长、自动发送规则、模型和语音策略。

取消与清理保持原所有权：

- 展示记录不创建或替换发送 claim，不把生成成功等同发送成功。
- 失败、超时、取消、账号变更与关闭均清理未 ready 的展示；前后台切换沿用原可见性与任务有效性保护。
- 取消排队任务不取消另一条正在使用共享生成器的任务；显式取消仍保留原终态防重。
- 全局配置失效仍走原取消路径；两端配置更新的先后顺序不会把自动延期误写为用户手动取消。
- 准备态不占 ready 预览名额；ready 队满时评论回复继续使用原 `deferred` 及可重试语义。
- 清理按 kind 和 task id 定位，评论回复不会误清除同 id 的私信展示。

普通 Overlay 被宿主移除/重挂的探针没有纳入此次生产修改；其中两项先被几何取整的前置断言阻断，不能当作已确认根因。原 `CommentRingOverlayTest` 已精确恢复为 0.2.21 基线，探针独立留档。

## 简单日志中的新诊断

历史 `[DouAi.ReplyOverlay]` 文字经 legacy 入口处理，简单模式不保留其原文；即使部分旧详细日志存在，也可能只留下引用散列。本轮增加受控的结构化 `automation_dispatch / reply_overlay_state`，只在展示状态变化时记录：

- 原因：`show_requested`、`tip_off`、`no_activity`、`empty`、`attach_failed`、`closed` 等。
- 回复通道、阶段、队列数、Activity 类型、提示开关和 View 的 attached/shown/parent_match 状态。
- 可用时关联原任务 trace，不输出消息正文、用户名称、目标 ID 或接口凭据。

`show_requested` 与 View 标志是程序观测，不等同于用户实际看到了位于其他窗口之上的像素；新记录用于区分后续剩余偶发情况，不把缺少日志本身当成故障。

## 验证与交付范围

本轮版本递增为 **0.2.22 / 123**。生产改动限定在 `CommentReplyHook` 和 `AutomationDispatcher`，另更新各自测试与版本信息，保留 0.2.21 的性能优化和更早查找器改动。

修改前的生成期缺窗回归已经失败；最终 13 套件 / 368 项专项零失败、零错误、零跳过，包含迟到主线程更新、两种配置更新顺序、共享生成器取消所有权、原生发送/账本、简单日志、抖音 40.8.0 原 APK 及最终签名包合同。最终签名包、元数据/DEX 合同、Lint、证书与对齐结果统一见 [0.2.22 发布记录](release-0.2.22.md)。0.2.21 的 2,430 项全量是独立基线，不计作本版重跑全量。

用户提供的旧实机日志不构成本次修复包的手机验收。当前已确认并修复准备阶段的历史显示缺口；成功发送但全程没看到窗口的其他偶发原因仍需由本版的受控展示记录与设备复验确认。本报告保留本地修复与验证范围，后续双端发布状态见上述 0.2.22 发布记录。
