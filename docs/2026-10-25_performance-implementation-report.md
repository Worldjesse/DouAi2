## 架构取舍与测量边界

R8 使用同一源码做了两次签名构建，仅 `app/proguard-release.pro` 不同：对五个纯策略类及内部类开放 `allowoptimization`，类和成员名称继续保留。原规则 APK 为 5,180,713 字节、DEX 共 4,853,512 字节；候选规则 APK 为 5,180,719 字节、DEX 共 4,853,564 字节。候选未产生体积收益，也没有真机运行时收益证据，因此最终恢复原保留规则。两组 APK、mapping、源码哈希及对比清单保存在 `work/performance-20261025/r8-before/`、`r8-after/` 与 `r8-comparison.json`，不将本轮运行时工作量下降归因于 R8。

本轮用反射访问器共享和消费者去重减少重复工作，没有将全部 Feed 功能重接到统一事件总线；不同功能读取时点与宿主可变对象的生命周期仍各自受控。位图没有池化，PixelCopy 和淡出资源所有权优先于复用。

64 MiB 是已接入瞬态位图的准入预算，48 MiB 是常驻模型历史图片的保守估算预算；它们不构成整个模块内存的硬上限。原始压缩输入、JSON 对象树、Native/GPU 资源、头像已有缓存，以及 μ-law WAV 验证的有界数组需在真机上继续一并测量。

scanner schema 更新会使旧扫描缓存一次性失效。冷启动和暖启动必须分别记录，A/B 暖启动均应先完成对应版本缓存预热。

本轮 `adb devices -l` 没有连接设备，因此没有安装宿主、执行 LSPosed 回调、真实 AI/语音请求或测得设备帧率、峰值内存及电耗。Robolectric、静态 DEX 和本地 HTTP fixture 不替代这些结果。

## 真机采集入口

在同一设备、同一宿主版本、同一内容与操作下，分别准备未注入、功能关闭、常用功能、重任务四组状态。每组先记录详细配置和调试日志模式，再运行：

```powershell
.\tools\measure-host-performance.ps1 -Serial '<adb devices 中的序列号>' -Scenario disabled -DurationSeconds 30
```

`Scenario` 可选 `uninjected`、`disabled`、`common`、`heavy`。该值由操作者声明，工具不声称已经验证注入状态。脚本保存系统 Trace、显示配置、宿主与模块包信息、前后 PSS、最近 FrameStats 和采集清单；不会自动启停应用或修改功能设置。FrameTimeline 取决于系统支持，FrameStats 为有限窗口，前后 PSS 不是峰值内存。脚本已通过 PowerShell 解析检查，设备执行尚未验证。

对照时优先查看帧截止时间、主线程和各 `DouAi-*` 线程 CPU 时间、GC、后台任务数量及完整任务延迟；电耗需要更长时间的受控重复实验。本轮没有远端发布。
