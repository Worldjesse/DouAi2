**0.2.6 / 107 已完成最终签名包严格本地验收：186 套件、1993 次执行，0 失败、0 错误、0 跳过；保持本地候选，本轮不发布远端。** 已验收的本地基线仍为 [0.2.5 / 106](release-0.2.5.md)，既有正式远端保持 0.2.4 / 105。当前状态统一见[构建与当前状态](releasing.md#当前状态)。

本轮响应用户反馈：“该视频被隐藏无法观看”提示后自动跳走，上滑也找不到该条，直接回到上上条。现有宿主文本证实了一条不经过旧删除 Hook 的安全校验自动移除链；修复前的真实调用形态夹具已实际跑红。但中文提示与该链的现场对应关系尚未通过 LSPosed/手机调用证据确认，不能据此声明手机问题已修复或视频可以播放。

## 本轮处理范围

0.2.5 中开关“不允许系统跳过已隐藏视频”只覆盖 `BaseListFragmentPanel.LJLJL(int, Aweme)` 和 FullFeed 同形 override。抖音 40.6.0 的安全校验回调另有两种任务：当前项先写召回 Set，再经事件、presenter 与 model 移除列表；非当前项直接调用 `IFeedDataContext.LJIIIIZZ(aid, "safety_check")`。仅挡旧方法不能覆盖这两条路径，只挡末端删除也可能留下召回标记，使下一次数据过滤再次移除条目。

本轮新增拦截限定到两个自动移除任务的执行时点：

| 目标 | 本轮条件 | 保留的宿主行为 |
| --- | --- | --- |
| `ALambdaS32S1500000_4.invoke(): Object` | 仅 `$t == 0` 的安全召回任务，且开关开启 | `$t == 1` 的独立删除分支、其他路径及任务之外的 `04Ov` bookkeeping |
| `LX/06ht.invoke(): Object` | 安全校验非当前项删除任务，且开关开启 | 开关关闭时的原生删除及其他 Feed 数据操作 |

被阻止的任务返回宿主 `kotlin.Unit`，避免改变回调返回合同；在任务真正执行时读取开关，使排队后的开关变化按当时设置生效。新增逻辑不把所有 `VideoEvent`、所有召回或所有错误都认作本次目标，不改写 Aweme 播放状态、服务端权限、风险标记或校验响应。它也不会恢复宿主此前已经移除的条目。

既有两个较宽的 LJLJL 保护仍保留；“两个窄任务”仅指本轮新增覆盖，不能据此声称所有手动删除都不受影响，`$t=1` 只表示未新增拦截的其他分支。

原 APK 身份、静态调用链、证据引用与本地红测见[隐藏视频跳过问题分析](2026-10-21_hidden-video-skip-report.md)。新增两个方法规则以及六项原 APK DEX 合同已分别确认任务身份、真实 packed-switch 的 `$t` 分支、bookkeeping 与排队顺序、召回标记先写后通知、非当前删除原因及下一次召回过滤；229 条规则全部唯一匹配。合成夹具与原 APK 合同分别报告。
