# 0.1.79：附件发送与后台自动回复

版本 `0.1.79 / versionCode 80`，面向抖音 `40.6.0 / 400601`。已构建、签名并归档。本版包含此前 0.1.77、0.1.78 的本地原生聊天布局、头像和输入控件更新，详细历史见 [0.1.77](release-0.1.77.md) 和 [0.1.78](release-0.1.78.md)。

## 用户可见变化

- 消息页聊天的图片和视频采用抖音原生选择器；文件继续使用系统文档选择器。
- 选择结果先显示为一个逻辑附件卡片，可继续填写文字、问题或说明。点击发送后才读取附件、抽取视频画面并请求模型。
- 视频不再在选择后展开为一排独立帧预览、文件名和重复删除按钮。删除卡片移除整个附件及其关联内容。
- 从原生相册返回后保留模型编辑器和测试聊天草稿，选择器自己的页面关闭按窗口归属处理。
- 视频仍按图片名额抽样画面，附带时长和抽样位置说明，不包含音频或语音；模型和接口必须支持图片输入。
- 读取、停止、失败重试、关闭和缓存释放属于本轮验收范围。此次调整不会自动缩短设备原生解码器的处理时间。
- 自动回复增加 SDK 全局消息通知入口，补齐旧数据库插入钩子的覆盖；未打开的会话从宿主本地异步读取后继续生成和发送。全局与数据库同一消息共用去重；临时查不到会话时释放预占，不会永久静默吃掉该消息。

## 使用

打开消息页 AI 联系人，点击附件入口选择图片、视频或文件。返回聊天页后核对附件卡片，可输入“请总结这段视频”等问题，再点击发送。只选择附件也需要点击发送；选完附件不会自动请求模型。

图片和视频选择界面使用宿主原生页面，但结果由模块暂存，发送请求仍走该 AI 联系人配置的接口。不会因为选择器外观来自抖音，就把附件发送给抖音好友。

更新模块后重启抖音。自动回复仍使用已配置的开关、对象范围、关键词、每日额度与间隔；私聊和群聊收到新消息后不要求进入对应聊天页，前提是宿主进程仍在运行并收到消息。评论回复的前台接收条件保持原有说明。

视频提供的是抽样图像，不能据此要求模型听取台词或判断未采样片段。文件范围与大小限制见[使用帮助](help.md#测试文字图片视频和文件)。

## 诊断依据

用户日志中，同一宿主后台线程出现两批各四次慢 `MediaMetadataRetriever` Binder 调用，每批已记录调用耗时累计约 24 秒。旧实现等待抽帧整体完成后才展开预览，又将同一个视频的帧和说明分两轮显示。

本轮将这些读取工作移到用户明确点击发送之后，并用单卡表达一个逻辑附件。具体证据、旧实现快照与取消限制见[附件诊断报告](2026-10-18_attachment-send-report.md)和[分析范围](attachment-send-scope.md)。日志中其他功能的语音合成 HTTP 402 不代表该次聊天视频视觉请求失败。

新增自动回复日志包有两次 SDK 发送确认和一次接口超时，缺少入站阶段记录，不能锁定每条用户消息的实际丢失点。本地旧逻辑已通过用例复现全局通知缺口和冷会话跳过；宿主 APK 证实旧 insert 钩子无法覆盖 replace/预编译写入，且同步会话 API 只查缓存。详见[自动回复分析](2026-10-18_background-auto-reply-report.md)。
