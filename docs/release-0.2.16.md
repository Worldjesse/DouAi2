## 累计修正

本次正式版包含 0.2.13 之后的本地变更：

- [0.2.14](release-0.2.14.md)：自动滑动钩子晚安装时恢复当前前台作品状态，Activity 暂停后拒绝迟到恢复；配置的长按动作消费抬手事件，保留触摸期间播放结束的原跳过规则。
- [0.2.15](release-0.2.15.md)：商品/购物卡与热点榜单卡使用独立默认关闭开关；附近广告纳入去广告，推荐商家限定为生活 SPU 场景，避免同类型音频卡误滤。已有保存值继续沿用。

上述历史候选的独立测试和产物保留各自范围，不计作 0.2.16 的本地验收次数。

## 纳入的改动

- 统一结构化日志入口与 schema 2。当前覆盖台账登记 58 项能力、28 个配置消费者族，区分启用、依赖、Hook 安装、实际观察和结果；扫描规则数量不作为业务功能数量。
- 根业务使用稳定 trace，跨异步、回调及重试关联；统一 success、failed、skipped、cancelled、timed_out、unconfirmed 六种结果，提交接受或 Hook 返回不单独作为业务成功。
- 全局调试开关同时控制模块文件与 LSPosed 输出。关闭时两处仅新增简单模式记录，保留状态、根开始/结果、必要原因、简要异常和完整性说明；开启时增加阶段、配置选择、Hook 安全类型/耗时及受限异常栈。关闭不会删除历史详细记录。
- 结构化事件从证据工作线程直接写入存储，消除第二个结构化待写队列；启动缓冲、分层损失台账、轮转、IO 回退和未闭合操作各有说明。简单模式仍更新受限内部阶段与私有 journal，以便下一次启动说明可恢复的中断操作。
- 记录异步任务接纳配置与原业务实际重读配置的不同版本；补充重复/迟到回调与信息流筛选原因。保持原有业务判断、配置读取时机、请求、过滤规则、返回、超时及重试行为。

完整说明见 [功能覆盖矩阵](logging-coverage.md)、[统一事件规范](logging-events.md)、[缺口修复交付报告](2026-10-23_logging-gap-repair-report.md)。后者保留源码修复阶段的原始测试结果和失败批次，不作为本版构建的全量验收结果。
