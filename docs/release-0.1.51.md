# DouAi 0.1.51

版本 `0.1.51` / versionCode `52`。沿用正式包名、原发布签名、R8 配置和抖音 40.6.0 适配规则；资源裁剪关闭。

## 故障依据

用户补充个别机型每次启动都出现“方法查找完成”，返回手势可以关闭，模块设置入口及功能开关仍可操作。粘贴日志记录模块 0.1.50 在 2026-10-13 16:36:45 启动，16:36:46.043 完成缓存读取：182 条规则全部唯一命中，`cacheHit=true`。因此这份日志没有显示反复重新扫描。

16:36:47.479 用户确认后请求重启，16:36:47.483 返回“重启中转组件不可用”；16:36:48.087/48.089 再次出现同一错误。失败发生于 `HostAppRestarter.AndroidScheduler.prepare` 的 `PackageManager.getActivityInfo` 前置查询。原实现尚未保存确认，也没有进入显式 startActivity 或结束进程阶段。

查询失败可能来自包可见性限制、模块隐藏、组件禁用或安装环境差异。日志不能区分这些原因，也不能以查询失败断言显式启动必然不可用；不应把它解释成 root 权限不足。

## 修正

- 删除中转 Activity 的强制查询前置检查，直接尝试启动既有显式组件；启动失败仍会被捕获。
- 成功扫描的确认先持久化，再尝试自动重启。安排、启动、握手或结束进程失败不撤销确认，提示手动重启；同一宿主/模块身份下的后续缓存命中保持静默。
- 返回手势关闭成功的完成提示也保存确认，不自动重启。扫描失败仍不确认；持久化失败仍保留可重试的提示。
- 中转页必须回传就绪后才能结束宿主进程。等待就绪上限 5 秒，超时后不结束进程，迟到回执也不会再触发结束。
- 异步结束进程异常被捕获；重启失败发生在宿主暂停期间时，手动重启通知延迟到宿主再次恢复显示。
- 保持宿主/模块身份变化后重新确认的规则。此次没有新增 root 命令、root 授权流程或其他权限。
